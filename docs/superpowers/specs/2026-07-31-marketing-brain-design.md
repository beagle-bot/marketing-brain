# Marketing Brain 设计说明

## 目标

在不修改现有 `brain` 项目的前提下，新建独立的 `marketing-brain` 项目。它每天从中国营销信源中筛选 30 条高价值内容，保留现有 Brain 的浏览、滑动筛选、手动收藏和本地记忆体验。

## 范围

### 包含

- 新的独立 Next.js 项目，默认目录名为 `marketing-brain`。
- 三个首批信源：SocialBeta、梅花网、数英。
- 每日总计 30 条：SocialBeta 12 条、梅花网 10 条、数英 8 条。
- 服务端规则筛选、去重和行业标签，不调用 LLM。
- Feed、收藏、我三个主要页面。
- 保留右滑记住、左滑略过，并支持点击按钮手动收藏。
- 收藏时保存原始条目快照和用户备注。
- Vercel 每日定时更新入口，目标时间为北京时间 08:00。
- Supabase 保存每日 Feed 批次和条目，客户端收藏仍默认保存在 localStorage。

### 不包含

- 不修改、搬迁或清理现有 `brain` 项目。
- 不接入付费内容 API。
- 不抓取微信公众号、小红书或微博登录后内容。
- 不使用 AI 评分、AI 摘要或向量检索。
- 不保留词云、Graph 页面或对应导航。
- 首版不做管理后台和信源编辑界面。

## 数据源

### 数英

- 使用公开 RSS `https://www.digitaling.com/rss`。
- 仅保留“文章频道”和“项目频道”，排除招聘频道。
- 从 RSS description 中提取纯文本摘要，原文链接指向数英。

### SocialBeta

- 从 `https://socialbeta.com/case` 读取最新案例文章和 campaign 入口。
- 必要时请求详情页补齐摘要、日期和品牌信息。
- 只读取公开页面，控制并发和超时。

### 梅花网

- 从 `https://www.meihua.info/shots` 页面的结构化 `__NEXT_DATA__` 中读取作品数据。
- 保留品牌、标题、摘要、发布日期、行业分类、原文链接和可用的互动数据。
- 优先使用梅花网自带行业分类。

## 统一数据模型

每条内容至少包含：

- 稳定 ID：来源名与规范化 URL 的哈希。
- 来源名和来源链接。
- 标题、摘要、作者或品牌。
- 原始发布时间和采集时间。
- 规则分数、选入理由。
- 行业标签和内容类型标签。

行业标签为：互联网、硬件、医药、汽车、金融、快时尚、茶饮、其他。标签只作为辅助信息，首版 Feed 不要求用户先选分类。

## 规则筛选

### 硬过滤

- 排除招聘、会议售票、纯公司公关稿、无摘要且标题信息不足的条目。
- 用规范化 URL 去重，再用标题归一化做跨来源近似去重。
- 已在近期批次出现的稳定 ID 不再入选。

### 规则评分

- 新鲜度：越新越高。
- 案例密度：标题或摘要含“案例、复盘、联名、campaign、传播、营销、社媒”等词加分。
- 信息完整度：有摘要、品牌、行业、发布日期的条目加分。
- 噪音惩罚：招聘、纯奖项通稿、纯商务推广、信息量过低的条目扣分。

各来源内独立排序后按 12/10/8 配额选入。某一来源当日不足时，从另外两个来源的候选列表按分数补齐，总数上限为 30。

## 行业分类

不使用模型。顺序为：

1. 使用梅花网原生分类映射。
2. 用品牌名和标题关键词匹配七个目标行业。
3. 无法判定时使用“其他”，不阻断入选。

规则表集中在单独配置文件中，方便后续修改，不散落在 UI 代码里。

## 每日更新与存储

- Vercel Cron 配置为 `0 0 * * *`，即 UTC 00:00，对应北京时间 08:00。
- Cron 路由校验 `CRON_SECRET`，防止未授权触发。
- 每次采集产生一个按中国日期命名的批次。
- Supabase 表包含 `marketing_feed_batches` 和 `marketing_feed_items`。批次日期唯一，重复 Cron 调用应幂等。
- Feed API 读取最新成功批次。
- 若当日抓取失败，不覆盖最后一个成功批次。
- 开发环境和未配置 Supabase 时，允许从本地示例批次运行界面。

Vercel Hobby 的 Cron 在目标小时内触发，不保证精确分钟；因此免费方案的产品承诺为“每天早上 8 点这个小时内更新”。

## 界面

### Feed

- 沿用现有 Brain 的移动端时间线和卡片风格。
- 显示来源、行业标签、标题、摘要、品牌/作者、发布时间。
- 保留滑动记住/略过。
- 提供明确的“收藏”按钮，不要求用户必须学会手势。
- 显示当日批次日期与条目数，数据源异常时显示简短状态。

### 收藏

- 保留收藏列表、有用性评级、备注和 Markdown 导出。
- 去掉与词云、AI 技术主题绑定的展示方式。
- 收藏条目保存原始快照，Feed 批次更新后仍可查看。

### 我

- 保留个人关注偏好和本地数据说明。
- 默认偏好改为营销策划与七个目标行业。
- 不将个人偏好发送给外部模型或内容站点。

## 错误处理

- 每个来源独立超时、独立记录错误，单源失败不拖垮整个批次。
- 抓取结果低于最低数量时，保留上一批并返回可诊断状态。
- 解析器只接受预期结构，站点页面改版时快速失败，不生成错乱条目。
- 客户端优先显示最后成功 Feed 缓存，网络错误不影响已收藏内容。

## 验证

- 为三个解析器保存小型 fixture，测试字段提取和页面改版失败。
- 测试招聘过滤、稳定 ID、跨源去重、规则评分、行业映射和 12/10/8 配额补位。
- 测试 Cron 授权、同日幂等和失败不覆盖。
- 运行 TypeScript 类型检查和 Next.js 生产构建。
- 用本地示例批次手动验证 Feed、收藏、略过、备注、重置和导出。

## 验收标准

- 原 `brain` 工作树没有因本项目产生新变更。
- 新项目可独立安装、运行、构建和部署。
- 开发环境能显示 30 条示例营销内容。
- 真实采集能从三个来源生成最多 30 条的当日批次，并满足配额和过滤规则。
- 整个项目不需要任何 LLM API Key，不产生模型 token 成本。
- 导航只包含 Feed、收藏、我，不出现词云入口。
